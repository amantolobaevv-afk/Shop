# AMAN BREND — Shop backend

Node.js 24 LTS + SQLite менен иштеген интернет-дүкөн. Тышкы npm пакеттер талап кылынбайт.

## Иштетүү / Запуск

1. Установите Node.js **24.15+ из ветки 24 LTS**.
2. Скопируйте `.env.example` в `.env`.
3. В `.env` задайте свой уникальный `ADMIN_PASSWORD` длиной от 16 символов. Пароль из примера сервер не примет. Не добавляйте `.env` в Git.
4. Выполните `npm start`.
5. Откройте `http://localhost:3000`. Панель владельца: `http://localhost:3000/admin.html`.

`PUBLIC_ORIGIN` должен точно совпадать с адресом браузера, включая порт. Если используете `http://127.0.0.1:3000`, измените эту настройку. Не открывайте HTML через `file://`: магазин обращается к серверному API.

```sh
npm start
npm test
```

Демо-каталог необязателен:

```sh
npm run seed
```

Seed создаёт 12 демонстрационных товаров с **нулевыми остатками**, чтобы примеры нельзя было случайно купить. Он не перезаписывает заполненную базу. Войдите в панель, замените фотографии и описания, укажите реальные цены и остатки, снимите флаг «Демонстрационная модель».

## Кардардын жолу / Покупка

Каталог → категория/поиск/размер → страница товара → цвет и размер → корзина или «Купить сейчас» → контактная форма → сохранение заказа на сервере → отправка подготовленного сообщения в WhatsApp.

- Цены, сумма и остатки проверяются сервером; присланная клиентом сумма не используется.
- Остатки учитываются отдельно для каждого цвета и размера.
- При создании заказа товар резервируется на 24 часа; по истечении неподтверждённого резерва остатки возвращаются.
- Подтверждённый менеджером заказ автоматически не истекает. Его нужно завершить либо отменить.
- Отмена возвращает остатки ровно один раз. Завершённые, отменённые и просроченные заказы окончательны.
- Доставка не входит в сумму товаров: её стоимость и сроки согласует менеджер.
- Номер и серверный статус заказа показаны после оформления. WhatsApp не считается подтверждением оплаты или отправки сообщения.
- `Idempotency-Key` защищает от повторного создания заказа при повторе одного запроса. Повтор ключа с другим содержимым отклоняется.
- Фото хранятся в `data/uploads`, данные — в `data/shop.sqlite`. Каталог общий для всех посетителей. Корзина остаётся в браузере.
- Старый локальный каталог из предыдущей версии автоматически не импортируется. Экспортируйте его заранее и перенесите реальные товары через панель.

## Ээсинин панели / Управление

`/admin.html`: вход по паролю → товары, фотографии, описание, материал, цена, категория, видимость и варианты `цвет / размер / доступный остаток`; список последних 200 заказов; подтверждение, завершение и отмена.

Остаток в форме — **свободное** количество, уже за вычетом резервов. Редактирование использует поле `version`: если другой запрос изменил товар, сервер попросит обновить данные вместо перезаписи. «Скрыть» убирает товар с витрины, сохраняя историю заказов.

Вход создаёт случайную сессию на 8 часов. Cookie: HttpOnly, SameSite=Strict, Secure в production. Изменения требуют CSRF-токен и совпадающий Origin. При перезапуске сервера все сессии завершаются. Пароль не хранится в коде или базе; сравнивается через scrypt. Есть ограничение попыток входа, создания заказов и загрузки фото. Перед проксированием IP из `X-Forwarded-For` не используется.

## API

Все тела запросов — JSON. Суммы в целых сомах (KGS), количество и остатки — целые числа.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка работы |
| GET | `/api/config` | Категории, контакты, доступность оплаты |
| GET | `/api/products?category=&q=&size=&sort=asc` | Каталог, фильтры; sort: asc/desc/default |
| GET | `/api/products/:id` | Товар и варианты с остатками |
| POST | `/api/orders` | Создать заказ, заголовок `Idempotency-Key` обязателен |
| GET | `/api/orders/:id` | Статус; нужен секретный `X-Order-Token` из ответа создания |
| POST | `/api/auth/login` | `{ "password": "..." }` |
| GET | `/api/auth/session` | Состояние сессии и CSRF-токен |
| POST | `/api/auth/logout` | Завершить сессию |
| GET/POST | `/api/admin/products` | Список / создание товара |
| PUT/DELETE | `/api/admin/products/:id` | Обновление с version / скрытие |
| POST | `/api/admin/uploads` | `{ "image": "data:image/jpeg;base64,..." }` |
| GET | `/api/admin/orders` | Последние 200 заказов, контактные данные только владельцу |
| PATCH | `/api/admin/orders/:id` | `{ "status": "confirmed|completed|cancelled" }` |
| POST | `/api/payments/checkout` | 503: платёжный провайдер пока не подключён |

Для всех изменяющих запросов необходим `Origin: PUBLIC_ORIGIN`. Для административных — cookie сессии и `X-CSRF-Token` из `/api/auth/session`.

Пример создания заказа:

```json
{
  "customer": "Аман",
  "phone": "+996503331717",
  "address": "Бишкек, улица, дом",
  "note": "Позвоните перед доставкой",
  "items": [{"variantId": 1, "qty": 1}]
}
```

Фото: JPG/PNG/WebP, максимум 6 на товар, каждый файл до 2 МБ после клиентского уменьшения. SVG не принимается. Проверяются сигнатуры форматов; имена генерируются сервером. Файлы, загруженные и затем убранные из формы, автоматически не удаляются — учитывайте место на диске.

## Онлайн-төлөм / Оплата

Платёжный сервис ещё не выбран. Реального списания денег и статуса «оплачено» в этой версии нет. API возвращает `onlinePayment: false`, попытка перейти к онлайн-оплате получает 503. Оплата согласуется с менеджером.

Для подключения провайдера отдельно понадобятся merchant-аккаунт и секреты, создание серверного платёжного запроса, проверка подписи webhook, проверка валюты/суммы/заказа и идемпотентная обработка результата. Возврат из браузера на success URL не должен подтверждать платёж.

## Размещение

Нужен сервер с Node.js и **постоянным диском**, один экземпляр приложения. GitHub Pages запускает только статику и не подходит для этого бекенда. Эта реализация Node/SQLite не является Cloudflare Worker и не загружается напрямую прежним статическим Sites-архивом.

Production-настройки:

```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=3000
PUBLIC_ORIGIN=https://your-domain.example
DATA_DIR=/data
ADMIN_PASSWORD=your-unique-secret-at-least-16-characters
```

Настройте HTTPS через reverse proxy, ограничьте доступ к диску с базой и резервным копиям. Не монтируйте `data/` как общедоступную папку. При смене пароля перезапустите сервер. Не запускайте несколько реплик с разными SQLite-файлами. Периодическая очистка резервов выполняется раз в минуту и при API-запросах.

Для согласованной резервной копии остановите приложение и скопируйте весь `DATA_DIR` (база и фото), затем запустите его. При восстановлении используйте ту же версию приложения и проверьте доступность фото. Заказы содержат контактные данные: ограничьте доступ к резервным копиям.

Docker: соберите `docker build -t aman-shop .`, затем задайте переменные окружения и подключите постоянный том к `/data`. Обеспечьте права на запись для UID 1000. HTTPS завершайте на внешнем proxy.

## Проверки и текущие границы

`npm test` проверяет цены, идемпотентность, откат неуспешного заказа, отсутствие перепродажи остатков, резерв/отмену, сохранность после перезапуска базы, сессии, CSRF, Origin, недоступность служебных файлов и ограничения оплаты. HTTP-обработчик проверяется без внешней сети. Визуальное браузерное тестирование и production-размещение не выполнялись.

Сохранён прежний дизайн, тёмная тема и частичный перевод RU/KY/EN/UZ. Полный перевод текстов товаров, SMS/email-уведомления, автоматическая доставка, личные кабинеты покупателей, возврат платежей и автоматическая сверка оплаты пока не реализованы.
